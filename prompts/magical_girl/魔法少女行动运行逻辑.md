# /魔法少女行动 运行逻辑

这份文档用于观察 `/魔法少女行动` 从命令触发到 AI 输出、再到变量写回的完整链路。

## 入口

用户发送：

```text
/魔法少女行动 去学校看看
```

入口在：

```text
main.py
  QQMahouShoujo.action_turn()
  QQMahouShoujo._run_action_turn()
```

旧入口 `/魔法少女日常` 和 `/魔法少女战斗` 已移除。`/魔法少女转生` 不变。

## 1. 命令解析

`main.py` 做这些事：

1. 确认是否允许在当前群使用。
2. 读取 `group_id` 和 `user_id`。
3. 使用玩家锁和群锁，避免同一玩家/同一群并发写存档。
4. 从命令后提取行动文本。

示例：

```text
命令：/魔法少女行动 去学校看看
action_text：去学校看看
```

然后调用：

```text
ActionTurnApplicationService.execute_action_turn()
```

## 2. 读取存档

服务位置：

```text
src/application/services/action_turn_application_service.py
```

它先通过：

```text
PlayerSaveRepository.load_player_save()
```

读取当前玩家数据：

```text
player_data_update.json 优先
player_data.json 兜底
daily_memory.jsonl 最近记录
cameo_memory.jsonl 其他人与主角的交互
```

行动阶段不再补齐默认骨架；这些顶层字段由 `/魔法少女转生` 生成。

本轮 AI 只能看到当前真实存档，也就是后面 `<status_current_variables>` 里的 `player_data_update.json` 快照。

## 3. 判断阶段

阶段从当前变量读取：

```text
/进程/阶段
```

目前只支持三种：

```text
日常
战斗
事件
```

如果缺失或非法，默认改成：

```text
日常
```

这里的默认只用于本轮读取判断，不会向存档写入补齐结构。

## 4. 上下文预处理

服务会根据阶段准备额外上下文：

```text
日常/事件：
  select_daily_context()

战斗：
  select_magical_battle_context()
```

这一步复用旧的目标选择能力，用于选出可能相关的：

```text
参与对象
魔物
场景事件
魔法少女目标
战斗胜率/节奏信息
```

胜率由 `ai_win_rate` 与 `desire_win_rate` 各占一半计算。程序在每个行动回合独立生成一个包含端点的 20-80 骰点；骰点大于胜率时失败，否则成功。首回合沿用目标选择阶段生成的骰点，续回合重新掷骰，保证同一回合只判定一次。

如果选择失败，会降级为空上下文，不影响主回合生成。

## 5. 构建酒馆式 Prompt

核心代码：

```text
src/infrastructure/analysis/analyzers/action_turn_analyzer.py
  ActionTurnAnalyzer.build_action_prompt()
```

主 prompt 模板在同目录：

```text
prompts/magical_girl/action_turn_prompt.txt
```

最终发给 AI 的 user message 按这个顺序拼：

```text
历史上下文
+ 阶段协议
+ 当前变量快照
+ 行动选项协议
+ 变量 API 文档
+ 后台事件协议
+ 示例库
+ master_protocol
= 一次完整 AI 回合
```

## 6. 每块 Prompt 的来源

### 历史上下文

来自：

```text
daily_memory.jsonl
cameo_memory.jsonl
玩家本轮 action_text
当前世界日期
```

用途：让 AI 知道最近发生过什么。

### 阶段协议

由代码按阶段生成：

```text
ActionTurnAnalyzer._phase_protocol()
```

阶段是 `日常` 时，要求写生活、训练、社交、轻量异常。

阶段是 `战斗` 时，要求动作优先、胜负和损耗必须来自正文。

阶段是 `事件` 时，要求自然推进正文，同时处理系统事件。

### 当前变量快照

格式固定：

```xml
<status_current_variables>
{ 当前 player_data_update.json }
</status_current_variables>
```

AI 只能根据这里读当前状态。

### 行动选项协议

要求 AI 在正文后输出：

```xml
<行动选项>
我去找使魔商量
我检查随身物品
我继续调查教室
我先休息一下
</行动选项>
```

程序会把每一行解析成选项。

### 变量 API 文档

由代码生成：

```text
ActionTurnAnalyzer._variable_api_document()
```

支持四种操作：

```json
{ "op": "replace", "path": "/路径", "value": "新值" }
{ "op": "delta", "path": "/数字路径", "value": 1 }
{ "op": "insert", "path": "/对象/新Key", "value": "内容" }
{ "op": "remove", "path": "/对象/Key" }
```

只读字段包括：

```text
/schema_version
/group_id
/user_id
/created_at
/updated_at
/nickname
/avatar_url
/世界/日期
```

### 后台事件协议

如果：

```text
/系统状态/待处理事件
```

不为空，就插入后台事件协议。AI 需要在正文正常推进的同时，在 JSONPatch 中处理并清理事件。

例如：

```json
{ "op": "remove", "path": "/系统状态/待处理事件/线索整理事件" }
```

### 示例库

由代码生成：

```text
ActionTurnAnalyzer._examples_library()
```

包含四类完整 `<UpdateVariable>` 示例：

```text
日常获得物品
战斗损耗
事件清理
世界观备注
```

用途是让 AI 模仿完整变量更新块，而不是只模仿零散 patch。

示例库里的每个场景都长这样：

```xml
<UpdateVariable>
  <Analysis>
    - 指令与事件：为什么要处理事件或不处理事件
    - 状态检查：本轮阶段、损耗、状态是否变化
    - 物品/位置/关系变化：正文中实际发生了什么
    - 长期记忆：是否需要登记世界观备注
  </Analysis>
  <JSONPatch>[
    { "op": "insert", "path": "/主角/道具栏/便签", "value": "写着今天的线索" }
  ]</JSONPatch>
</UpdateVariable>
```

注意：示例库只是“模仿样板”。真正的硬性输出格式仍由下面的 `UpdateVariable_block` 决定。

## 7. AI 必须输出什么

AI 输出必须是：

```text
故事正文

<行动选项>
选项1
选项2
选项3
选项4
</行动选项>

<UpdateVariable>
  <Analysis>
    - 指令与事件：
    - 状态检查：
    - 物品/位置/关系变化：
    - 长期记忆：
  </Analysis>
  <JSONPatch>[
    { "op": "replace", "path": "/主角/生理状态/当前生理动态", "value": "呼吸平稳" }
  ]</JSONPatch>
</UpdateVariable>
```

## 8. 解析 AI 输出

解析代码：

```text
ActionTurnAnalyzer.parse_action_turn_response()
```

它会提取：

```text
story_text：<行动选项> 之前的正文
action_options：<行动选项> 每一行
analysis：<Analysis> 内容
json_patch：<JSONPatch> JSON 数组
raw_response：原始回复
```

如果缺少 `<UpdateVariable>` 或 `<JSONPatch>`，本轮会失败，不写存档。

## 9. 应用 JSONPatch

应用代码：

```text
PlayerSaveRepository.apply_json_patch()
```

保存代码：

```text
PlayerSaveRepository.save_action_turn_result()
```

执行流程：

```text
读取当前 player_data_update.json
校验 JSONPatch
应用 replace/delta/insert/remove
写回 player_data_update.json
写入 daily_memory.jsonl，并记录群内绝对 conversation_no
每次成功行动递增 conversation_no
事件完成时至少推进一天；剧情明确跨日时可通过 /世界/日期 的正整数 delta 推进多天
```

## 12. 为什么不把 action_turn_analyzer.py 放进 prompts 目录

`prompts/` 是可编辑文本资源目录，适合放 prompt 和说明文档。

`action_turn_analyzer.py` 是 Python 运行代码，需要待在 `src/` 包结构里才能被正常导入、编译和测试。

所以现在的观察方式是：

```text
prompt 和说明：
  prompts/magical_girl/action_turn_prompt.txt
  prompts/magical_girl/魔法少女行动运行逻辑.md

运行代码：
  src/infrastructure/analysis/analyzers/action_turn_analyzer.py
```

这样 prompt 和说明贴在一起，代码仍保持项目结构干净。

## 13. 实际发送给 AI 的 messages

`/魔法少女行动` 不是只把完整 prompt 作为单条 user message 发送，而是先用两轮自然对话建立“小猫之神已经答应担任 DM”的上下文，再提交完整运行时 prompt：

```json
[
  {
    "role": "system",
    "content": "可编辑的默认 system prompt"
  },
  {
    "role": "user",
    "content": "喵喵喵——伟大又可爱的小猫之神，请聆听信徒最虔诚的呼唤——"
  },
  {
    "role": "assistant",
    "content": "喵——哈~ 刚睡醒就来找本喵，是什么事呀喵？"
  },
  {
    "role": "user",
    "content": "想请小猫之神主持魔法少女互动故事，小鱼干已经准备好啦，请在故事外当 DM 并使用第三人称。"
  },
  {
    "role": "assistant",
    "content": "好耶喵，那就让小猫之神来当 DM 吧，小鱼干可要说话算话！本喵会用第三人称写故事并整理状态变化。"
  },
  {
    "role": "user",
    "content": "历史上下文 + 阶段协议 + 当前变量快照 + 行动选项协议 + 变量 API + 后台事件协议 + 示例库 + master_protocol + 玩家本轮行动"
  }
]
```

对应代码：

```text
src/infrastructure/analysis/analyzers/action_turn_analyzer.py
  ActionTurnAnalyzer._build_action_messages()
```

含义是：

```text
system:    保留可编辑的基础规则。
user:      自然召唤小猫之神。
assistant: 小猫之神醒来回应。
user:      用小鱼干邀请它在故事外担任 DM，并约定第三人称。
assistant: 小猫之神自然答应主持故事和维护状态。
user:      提交完整运行时 prompt 与玩家本轮行动，模型继续沿用刚建立的身份回复。
```

debug 模式会额外保存：

```text
action_turn_messages
```

这里可以直接看到本轮真正发出的四条消息。如果当前 AstrBot Provider 不支持 `messages` 参数，底层会自动回退成旧的 `prompt + system_prompt` 发送，避免行动命令直接失败。
